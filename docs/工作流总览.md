# 工作流总览

> 三系统（飞书多维表 + Moka + 简历筛选框架）串成的端到端招聘评估工作流。
> 决策依据见本文件夹 CLAUDE.md。

## 数据流

```
你给 Agent 职位描述
   └─Step1─> 飞书职位表（写记录，拿 record_id）
                └─Step2─> 读回职位 -> 本地派生岗位画像 -> 建三区工作区
                              ├─ 简历库/  ←Step3─ Moka 复制 PDF+JSON（带面试结论标签，moka-fetch 抓到 moka_output）
                              ├─ 待评估/  ←Step3─ 你手动上传外渠道 PDF
                              └─ 评估完成/{被接收,未通过,待定}/
   Step4：简历库 PDF -> pymupdf 提 txt -> Agent 8 维评估 -> 用 Moka 标签做群体分析
          └─> 评估参考_<职位>_<日期>.md（=群体分析报告）+ 评估结果表(来源=简历库)
   Step5：待评估 PDF -> pymupdf 提 txt -> Agent 8 维 + 评估参考校准 -> 单人评估卡(备注)
          └─> PDF+评估卡搬进 评估完成/<verdict>/ + 评估结果表(来源=待评估)
```

## 五步细则

### Step 1：职位入表
- **输入**：你在对话里给 Agent 职位描述 + 相关信息
- **Agent**：把描述映射到职位表 15 字段（职位名/JD/薪资/毕业时间/时长要求/关注点/排除项/...）。select 字段须用既有选项值（写前查 `+field-list`）
- **脚本**：`step1_write_job.py 职位字段.json` 写飞书职位表
- **产出**：record_id（回填职位同步映射，供 Step2/5 关联）

### Step 2：读表建区
- **脚本**：`step2_setup_workspace.py "职位名"` 读职位表该行 + 建三区目录
- **Agent**：据脚本打印的字段（JD + 关注点 + 排除项 + 毕业时间 + 时长要求）按 `templates/岗位画像模板.md` 派生 `工作区/<职位>/岗位画像_<职位>.md`
- **三区**：`简历库/` `待评估/` `评估完成/{被接收,未通过,待定}/`
- **画像不进多维表**（职位表 schema 不动），是本地派生产物

### Step 3：三区就位
- **简历库**：先把简历库源填好（三选一：① 跑可选子流程 `node moka/moka-fetch.js "Moka职位名" ["阶段"]` 抓到 `moka_output/`，需 CDP Edge + Moka 登录，见 `moka/README.md`；② config 指向已有 Moka 数据；③ 手工放 PDF+JSON），再 `step3_copy_moka_library.py "飞书职位名"`
  - 按 `config.moka_job_map` 找 Moka 目录，从 `moka_resumes_root/<Moka目录>/<阶段>/` **复制** PDF+JSON 进 `简历库/`（原件不动）
  - 聚合每份 JSON 的 `conclusions[].result` -> `简历库标签.md`（姓名｜面试结论｜面试官｜面试时间）
  - ⚠️ 标签只在面试结论提交后有意义。面试没面完就跑，大片「未面」。刷新 = 重抓 Moka + 重跑
- **待评估**：你手动把外渠道简历 PDF 放进 `待评估/`
- **评估完成**：Step5 填充

### Step 4：简历库 -> 评估参考
- **脚本**：`step4_extract_pdf.py "工作区/<职位>/简历库"` 用 pymupdf 提 txt 到 `简历库/txt2/`（严格按 `docs/PDF文本提取方法.md`：水印正则、质量校验、扫描件标红需 OCR）
- **Agent**（按 `docs/评估框架/`）：
  1. 读每份 txt2，按 `01-数据规范.md` 建 Candidate 档案
  2. 按 `02-评估框架.md` 8 维打分（基准=岗位画像）+ 写综合评估段，产出 `单人评估卡`（`templates/单人评估卡模板.md`）
  3. 按 `03-群体分析方法论.md` 做群体分析：**用 Moka 面试结论当真实标签**，通过组 vs 淘汰组对比、区分性特征、拒因聚类
  4. 产出 `评估参考_<职位>_<日期>.md`（= 群体分析报告，`templates/群体分析报告模板.md`）
- **脚本**：每份评估 `step5_write_eval_result.py 简历库评估.json`（来源=简历库，带 Moka面试结论列）写飞书评估结果表

### Step 5：待评估 -> 评估完成
- **脚本**：`step4_extract_pdf.py "工作区/<职位>/待评估"` 提 txt
- **Agent**：
  1. 读 txt2，建档案
  2. 按 8 维 + **以 Step4 的评估参考为校准基准**打分 + 写综合评估段 -> 单人评估卡（这就是「备注」）
  3. 定 verdict（被接收/未通过/待定，按 `02-评估框架.md` 评级阈值）
- **Agent**：把待评估 PDF + 评估卡搬进 `评估完成/<verdict>/<姓名>.pdf + <姓名>.md`
- **脚本**：`step5_write_eval_result.py 待评估评估.json`（来源=待评估）写飞书

## 其他产出物（职位根目录）

以下产出物位于 `工作区/<职位>/` 根目录，是工作流过程中产生的辅助文件：

| 产出物 | 产生阶段 | 说明 |
|---|---|---|
| `单人评估卡总览_<职位>_<日期>.md` | Step5 | Agent 评估待评估区一个批次的逐人 8 维汇总（一个 md 放多人，含评级/总分/verdict/8 维打分）。区别于「单人评估卡」：总览是评估过程的批量汇总，单人卡（一人一 md）是评估后归档到 `评估完成/<verdict>/`。 |
| `待评估筛选报告_<日期>.md` | Step5 | Agent 对待评估区的筛选决策报告，分「合适(推面试)/待定(备选)/无法评估(需OCR)」三档，带估分和主因。是评估前的筛选中间产出。 |
| `feishu_chat_manifest.json` + `feishu_chat_resumes/` | Step3 | 脚本 `scripts/feishu_chat_download.py` 从飞书群聊自动拉的简历，是 Step3「待评估」区简历的来源渠道之一（替代手动放 PDF）。manifest 记录每条消息的 file_name/file_key/群里 CheckMark 反应/pass 标记；`feishu_chat_resumes/` 存下载的 PDF（含 txt2/）。 |

> 三区（简历库/待评估/评估完成）+ 画像 + 评估参考 是规范核心产物；上表是过程辅助产物，评估完成后可按需归档或清理。

## 飞书两张评估表

`setup_eval_table.py` 一次性建两张，所属职位 link 关联职位表。`step5` 按「来源」分派。

**评估结果表**（来源=待评估）：

| 字段 | 类型 | 说明 |
|---|---|---|
| 姓名 | text | 主属性列 |
| 所属职位 | link->职位表 | 关联 |
| 评级 | select: A/B/C+/C | 8 维总分映射（A=推面试/B=电话初筛/C+=备选/C=拒） |
| 评估详情 | text | 综合评估精简版（结论+核心依据+关键判断，~200字） |
| 核心原因总结 | text | 一句话合适/不合适原因 |
| 评估日期 | text | |
| 评估卡路径 | text | 指向本地 md |

**moka简历库表**（来源=简历库）：评估结果表的字段 + `Moka面试结论`(通过/待定/淘汰/未面) + `评估卡内容`（文字摘要，预留暂不写）。

核心价值：moka简历库表里直接看「评级（Agent 推荐）vs Moka 面试结论（真实标签）」校准；评估结果表是当前待评估的产出。与本地三区 1:1 对应（简历库区↔moka简历库表，评估完成区↔评估结果表）。

## Moka 标签聚合规则

一人多面试官，按优先级取一个标签：
1. 任一「通过」-> 通过
2. 否则任一「淘汰」-> 淘汰
3. 否则任一「待定」-> 待定
4. 全 null -> 未面

## 已定决策清单

1. 飞书 user 身份操作（免协作者免审）
2. 用多维表 `<app_token>...`（职位表 `<table_id>`）
3. 岗位画像本地派生，职位表 schema 不动
4. 简历库/待评估 = 同职位不同渠道（简历库=Moka带标签，待评估=外渠道）
5. 标签 = Moka `conclusions[].result`（通过/待定/淘汰/未面）
6. 简历库 = 复制 Moka（B 方案，原件不动）
7. PDF 提取只用 pymupdf（严格按 docs/PDF文本提取方法.md）
8. 评估复用 8 维框架（02-评估框架.md），不另造
9. 备注 = 单人评估卡 md
10. 评估结果表两步都写（A 方案，来源区分）
11. 评估参考 = 群体分析报告（Moka 标签当真实标签）

## 已知职位映射

> ⚠️ `config.moka_job_map` 是从 Moka 线上更新而来的带时间戳快照（见 `moka_job_map_updated_at`），日常可以 map 为准，但与线上当前状态可能有差距。**不自动同步**：不每次运行都自动去线上刷新，由 Agent 提醒「map 可能过期」、用户决定是否从线上重新拉取并更新 map。下表是已知映射的备忘。

- **客户端开发（U3D）≡ 客户端实习生（U3D）**：同一职位的两个飞书名，`moka_job_map` 都映射到 Moka 目录「客户端开发（U3D）」。评估时 `工作区/客户端开发（U3D）` 与 `工作区/客户端实习生（U3D）` 两个文件夹当一个池子——基准用 `岗位画像_客户端实习生（U3D）.md`，校准用 `评估参考_客户端开发（U3D）_<日期>.md`，不纠结候选人在哪个文件夹下。
