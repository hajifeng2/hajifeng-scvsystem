# 01 - 数据规范

> 数据层是地基。数据源选错或字段不统一，上层分析全部失真。

## 1. 数据源

### 标准数据源要求
简历 PDF 需提取为干净文本。提取质量标准：
- 正文可读，无水印/编码碎片污染
- 联系方式、项目、技能等关键信息完整
- 若提取质量差（水印污染正文、乱码、碎片化），**必须换工具重提，不得将就**

> **经验教训**：PDF 提取常把水印 hash 插入正文。劣质提取会把水印切成碎片散落全文，导致联系方式被切碎、正文不可读。务必逐份校验提取质量。

### 原件保护
- PDF/原始简历**只读**，不修改/改名/删除
- 文件名常编码求职意向（岗位/地点/薪资/届次/到岗/时长），**不得改名**，改名会丢失这些信息

## 2. 清洗规则

分析前对文本做以下清洗（填档案时同步完成）：

| 噪声 | 形态 | 处理 |
|:---|:---|:---|
| 水印 hash | 末尾形如 `xxxxx~~` | 删除 |
| 分页符/页眉页脚 | `[--- page break ---]` 等 | 删除 |
| 散落联系方式 | 电话/邮箱混在正文 | 提取到 frontmatter `phone`/`email` |
| 连续空行 | | 压缩为单个 |

## 3. Candidate Schema（通用字段）

每候选人档案用 YAML frontmatter 存以下字段。必填缺失填 `未知` 并在评估时标注风险。

### 基本信息
| 字段 | 必填 | 说明 |
|:---|:---:|:---|
| name | ✅ | 姓名（以简历正文为准） |
| alias | ⬜ | 文件名拼音/别名，与正文名不一致时记 |
| phone | ✅ | 电话（脱敏） |
| email | ✅ | 邮箱（脱敏） |
| gender / age | ⬜ | |

### 教育背景
| 字段 | 必填 | 说明 |
|:---|:---:|:---|
| school | ✅ | 学校 |
| major | ✅ | 专业 |
| degree | ✅ | 本科/硕士 |
| school_tier | ✅ | 985/211/双非/职业本科等（按当地教育体系标注，评估用） |
| edu_start / edu_end | ⬜ | 入学/毕业时间 |
| gpa_rank | ⬜ | 绩点/排名 |

### 求职意向（从文件名或简历提取）
| 字段 | 必填 | 说明 |
|:---|:---:|:---|
| position | ✅ | 期望岗位 |
| location | ✅ | 期望地点 |
| grad_year | ✅ | 届次 |
| salary / availability / duration | ⬜ | 薪资/到岗/时长 |

### 项目经历（列表，每项）
| 字段 | 必填 | 说明 |
|:---|:---:|:---|
| name | ✅ | 项目名 |
| period | ✅ | 时间跨度 |
| role | ✅ | 角色 |
| tech_stack | ✅ | 技术栈 |
| role_ratio | ✅ | 投递方向模块占比（估，0-100%） |
| originality | ✅ | 原创 / 教程复刻 / AI生成 |
| verifiable | ✅ | 是否有可验证链接 |
| highlight | ⬜ | 核心亮点 |

### 其他
| 字段 | 必填 | 说明 |
|:---|:---:|:---|
| internship | ⬜ | 实习经历（有/无 + 描述） |
| competitions | ⬜ | 竞赛奖项 |
| links | ⬜ | GitHub/视频/演示等可验证链接 |
| skills | ✅ | 技能清单 |

### 分析标签（评估时填）
| 字段 | 必填 | 说明 |
|:---|:---:|:---|
| result | ✅ | 被接收 / 未被接收 / 待定 |
| reject_reason | ⬜ | 未通过者必填，见 `02` 拒因分类 |
| reject_reason_secondary | ⬜ | 次因 |
| score | ⬜ | 单人评估总分 |
| tier | ⬜ | A / B / C+ / C |

## 4. 档案文件格式

```markdown
---
name: 张三
phone: 138****1234
email: abc****@qq.com
school: 某大学
major: 某专业
degree: 本科
school_tier: 双非
grad_year: 27届
position: 某岗位
result: 被接收
score: 85
tier: A
projects:
  - name: 某项目
    period: 2025.10-2026.03
    role_ratio: 90%
    originality: 原创
    verifiable: true
links:
  - https://...
---

# 张三 - 原始简历文本（清洗后）

（粘贴清洗后的正文，保留项目描述细节，供评估引用证据）
```

## 5. 分类与命名

- 档案目录：`candidates/被接收/`、`candidates/未通过/`、`candidates/待定/`
- 档案文件名：`<姓名>.md`（用姓名而非拼音，避免不一致）
- 姓名与文件名/内容不一致时，以**简历正文姓名**为准，`name` 记正文名，`alias` 记文件名别名

## 6. 岗位特定项不进档案

**加分词、风险词、红线、学历门槛等岗位特定项放岗位画像**（见 `templates/岗位画像模板.md`），不放候选人档案。档案只记客观事实，使档案可跨岗位复用、跨批次对比。
