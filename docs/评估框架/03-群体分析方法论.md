# 03 - 群体分析方法论

> 这是"综合分析"区别于"逐人报告"的核心。从个体打分上升到群体规律，提炼可解释的判据。

## 1. 分析输入

- 已完成的 `candidates/` 全部档案（含 `score` / `tier` / `result` / `reject_reason`）
- 岗位画像（评估基准）
- **真实标签源**（校准 Agent 评估用，二选一或互补）：
  - **Moka 面试结论** `conclusions[].result`（通过/待定/淘汰）：面试结论提交后才有意义，Step3 聚合进 `简历库标签.md`。本方法论默认标签源。
  - **飞书群 CheckMark**：招聘者在职位群（如「客户端实习生招聘群」）的简历消息上回复 CheckMark = 通过、无 = 未通过，比 Moka 面试结论更直接反映招聘者决策。拉取：`scripts/feishu_chat_resumes.py --chat-id <id> --start <ISO>` 输出 manifest（含 CheckMark 标签），`scripts/feishu_chat_download.py --manifest <m> --to <dir>` 下载 PDF；走 `lark-cli im`（user 身份），查群 `lark-cli im +chat-search --query <群名>`。

## 2. 五步群体分析

### 步骤一：对比矩阵（通过组 vs 未通过组）

按 `02` 的维度，分别计算两组的均值/分布，输出对比表：

| 维度 | 通过组均值 | 未通过组均值 | 差值 | 区分力 |
|:---|:---:|:---:|:---:|:---:|
| D2 项目积累 | | | | 高/中/低 |
| D3 原创可信度 | | | | |
| D4 岗位技术匹配 | | | | |
| D5 可验证性 | | | | |
| D6 方向匹配 | | | | |
| D7 工程素养 | | | | |
| D8 格式与逻辑 | | | | |

**区分力判断**：差值越大且组内方差越小，区分力越高。区分力"高"的维度是下一步提炼的重点。
**待定者**不纳入两组统计，单独在步骤五讨论。

### 步骤二：区分性特征提炼

从区分力"高"的维度提炼为**可解释的判据**：

- **否定判据**：出现 X 特征 -> 未通过概率 >80%
- **肯定判据**：同时满足 A+B+C -> 通过概率 >80%

每条判据附支持案例（通过组/未通过组各举 ≥2 人，引用原文），并统计命中率（如"未通过组 3/4 命中，通过组 0/4 命中"）。

### 步骤三：拒因聚类

对未通过组按 `reject_reason` 聚类，每类输出：

| 拒因 | 人数 | 共性特征 | 典型案例 | 可挽救度 |
|:---|:---:|:---|:---|:---|
| AI代写 | | | | 高/中/低（改了能否变通过） |
| 方向错配 | | | | |
| 教程复刻 | | | | |
| 积累太薄 | | | | |
| 学校弱 | | | | |

### 步骤四：通过者画像

归纳通过组的共性，输出"通过者画像"：

- **硬性共性**：学历/届次/项目数/跨度等
- **技术共性**：命中哪些岗位刚需技能
- **软性共性**：可验证性/工程素养/原创度

画像用于下一批的快速识别（看到这些特征 -> 优先推面试）。

### 步骤五：边界案例讨论

- **待定者**：差什么才能升级为通过？给出具体补强建议
- **反常者**：学历好却拒 / 学历弱却过 -- 解释某维度如何压倒学历
- 边界讨论防止规则僵化，避免一刀切

## 3. 产出

按 `templates/群体分析报告模板.md` 输出一份群体分析报告。

## 4. 注意事项

- 群体规律基于小样本（单批 <30 人）时，结论标注"初步规律"，**不绝对化**
- 区分性特征需附原文证据，不得仅凭印象
- 边界案例必须讨论，避免规则僵化
- 拒因聚类时，一人命中多个拒因，取**主因**（最致命的那个），次因记入 `reject_reason_secondary`
