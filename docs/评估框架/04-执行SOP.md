# 04 - 执行 SOP

> 新批次简历到了，按本流程跑。全程无代码，由 AI 按规则执行。

## 前置：定义岗位画像（必须先做）

每批分析前，用 `templates/岗位画像模板.md` 定义本次岗位的：

- 岗位名称 / 地点 / 薪资
- 届次 / 到岗 / 时长要求
- 学历门槛
- **岗位刚需技能**（D4 加分词：必须命中 + 加分命中）
- **方向匹配词**（D6 加分词 + 风险词）
- 红线（不可接受项）

岗位画像是评估基准，**必须先定**。不同岗位的 D4/D6 加分词不同，不定画像无法打分。

## 执行步骤

### Step 1：入库与提取
1. 简历原件放对应结果文件夹（被接收/未被接收/根目录待定）
2. 提取为干净文本，逐份校验质量（**具体方法见 `PDF文本提取方法.md`**，推荐 pymupdf，已验证）
3. 若提取质量差（水印污染正文、乱码），换工具重提

### Step 2：填结构化档案
对每份简历，按 `01-数据规范.md` 的 Schema 创建 `candidates/<结果>/<姓名>.md`：
1. 清洗（去水印 hash / 分页符）
2. 提取字段填 frontmatter（隐私脱敏）
3. 粘贴清洗后正文到档案正文区
4. 填 `result` 标签

### Step 3：单人评估
对每份档案，按 `02-评估框架.md`：
1. 逐维度打分，附原文证据
2. 检查红旗信号（命中即扣分或归零）
3. 汇总总分 -> 评级
4. 填回 frontmatter 的 `score` / `tier` / `reject_reason`
5. 产出单人评估卡（`templates/单人评估卡模板.md`）

### Step 4：群体分析
按 `03-群体分析方法论.md` 五步：
1. 对比矩阵
2. 区分性特征提炼
3. 拒因聚类
4. 通过者画像
5. 边界案例讨论

### Step 5：产出报告
用 `templates/群体分析报告模板.md` 输出 `群体分析报告_<岗位>_<日期>.md`。

### Step 6：迭代回写
若发现新规律/红旗信号，回写 `02-评估框架.md`，更新末尾变更日志。

## 电话初筛 3 问（B 级候选人用）

简历有疑点但不想直接拒时，根据岗位定制 3 个问题，典型维度：

1. **验证原创性**："XX 项目哪个模块你独立设计的？如果让你做 XX 扩展，你会改哪些代码？"
2. **验证深度**："XX 技术遇到过的最难的 bug 是什么？"
3. **验证方向**："这个岗位哪个模块你最感兴趣？如果只能选一个方向你选哪个？"

判定标准：只会描述现有结构/答不上来/方向模糊 = 红旗；能说扩展思路/具体 bug/明确方向 = 真实。

## 流程图

```
岗位画像 -> 入库提取 -> 填档案 -> 单人评估 -> 群体分析 -> 报告 -> 迭代回写
```

## 每批结束前的检查清单

- [ ] 所有简历已提取干净文本且质量合格
- [ ] 所有候选人档案字段完整（必填无缺）
- [ ] 所有档案有 `score` / `tier`
- [ ] 未通过者有 `reject_reason`
- [ ] 群体报告含五步分析
- [ ] 新规律已回写 `02`
- [ ] 隐私字段已脱敏
